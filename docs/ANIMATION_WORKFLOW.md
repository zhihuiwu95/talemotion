# TaleMotion 动画生产流程标准 v1

## 你需要提供什么

最低输入只有一项：**故事情节**。

如果没有额外说明，TaleMotion 采用以下默认值：

- 语言：简体中文
- 时长：约 2 分钟
- 画幅：16:9，1280 × 720
- 受众：亲子共读 / 6–10 岁
- 旁白：单人普通话
- 形式：2D 动态绘本，不追求逐帧视频
- 交付：可交互网页、字幕、旁白、全屏播放

只有会显著改变结果的问题才需要追问，例如“写实恐怖”与“低龄温暖”之间的选择；其余细节由制作流程补全。

## 标准生产物

每个故事最终形成一个独立 Story Package：

    stories/<story-id>/
    ├── brief.md                  # 原始情节、默认值和已确认约束
    ├── story-bible.json          # 角色、世界观、固定视觉特征
    ├── storyboard.json           # 6–8 个场景及叙事节拍
    ├── assets/
    │   ├── characters/
    │   ├── backgrounds/
    │   ├── props/
    │   └── audio/
    ├── scenes/
    │   ├── 01-*.scene.json
    │   └── ...
    └── manifest.json             # 场景顺序、总时长、版本

当前单 Scene Runtime 仍把演示文件放在 src/demo/；引入多 Scene 播放器时再迁移到上述 Story Package，避免现在创建一个运行时尚不能消费的目录结构。

## 七步流程

### 1. 情节归一化

把用户情节整理成一句主题、开端、阻碍、转折、高潮和结尾。锁定不能擅自改变的人物与设定。

质量门：故事在目标时长内可讲完，人物动机与结局清楚。

### 2. 故事圣经

为每个角色建立稳定 ID、外观锚点、性格、比例和表情表；为世界建立色彩、光线、材质和镜头语言。

质量门：任何场景只看 ID 和圣经，就能画出同一个角色。

### 3. 分场与时间预算

2 分钟默认拆为 6–8 场，每场 12–20 秒。旁白先分段，再为动作留出呼吸时间。

质量门：每场只有一个主要叙事目的，所有场景总时长与目标误差不超过 5%。

### 4. 资产清单与生成

先列清单，再生成背景、角色状态和可动道具。凡是需要移动、旋转、显隐或交互的元素必须拆成独立透明资产。

质量门：尺寸、透明通道、命名、角色一致性和文件可读取全部通过。

### 5. TTS、字幕与声音

生成分段旁白音频和时间戳；字幕由真实时间戳产生。生产环境密钥只放服务端，播放器只读取生成后的音频资产。

质量门：音频可播放、无截断；字幕与句子边界一致；缺失音频时动画仍可运行。

### 6. Scene JSON 编排

Director 使用动作白名单输出 Scene JSON。所有目标使用绝对值，避免重播累积偏移；任何新动作必须先扩 Schema 和 Action Registry。

质量门：

    npm run scene:validate
    npm test
    npm run lint
    npm run build

### 7. 浏览器验收

至少检查：首次播放、暂停、恢复、连续重播、字幕、旁白降级、桌面布局、移动端布局、全屏进入/退出以及结尾状态。

质量门：无控制台错误，120 秒终点显示 02:00 / 02:00，重播恢复初始画面。

## “请做第二个动画”的固定交互

以后你可以直接这样说：

> 新故事：一只害怕下雨的小狐狸，为了把药送给森林另一边的奶奶，第一次独自穿过暴雨。

TaleMotion 应直接返回并执行：

1. 对故事的简短理解和采用的默认值。
2. 场景节拍表与资产清单。
3. 需要生成或复用的素材。
4. 受 Schema 约束的场景文件。
5. 中文 TTS 与字幕。
6. 自动校验和浏览器验收结果。

除非存在会改变主题、受众或视觉安全性的歧义，否则不要求用户先填写长表单。

## 完成定义

第二个动画只有同时满足以下条件才算完成：

- 故事不是写死在 React、PixiJS 或 Action Handler 中。
- 所有场景在播放前通过 Schema 和本地素材校验。
- 角色 ID 与视觉锚点跨场景一致。
- 动画、字幕和声音都有明确时间来源。
- 播放、暂停、重播、全屏和降级路径经过验证。
- README 与故事包能让下一次制作直接复用。
