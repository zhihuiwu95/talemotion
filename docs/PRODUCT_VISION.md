# TaleMotion 产品理解与最终形态

## 一句话判断

TaleMotion 不是“输入一句话直接生成一段不可控视频”，而是一个 **AI 原生动态绘本生产引擎**：AI 负责理解故事、拆镜头、生成素材和旁白，稳定的 Scene Runtime 负责可重复、可校验地把它演出来。

核心资产不是某一段动画，而是：

    故事情节
      → 故事圣经（角色、世界观、风格）
      → 分场与镜头计划
      → 角色/背景/道具/音频资产
      → 经过 Schema 校验的 Scene JSON
      → 可交互播放器
      → Web 动态绘本 / 视频导出

## 最终用户体验

用户只需要提供故事情节。系统在确有必要时追问受众、时长或画风，其余采用明确默认值，然后完成：

1. 把故事改写成适合动画表达的节拍和旁白。
2. 创建并锁定角色设定，保证跨场景形象一致。
3. 将 2 分钟故事拆成约 6–8 个、每个 12–20 秒的场景。
4. 为每个场景生成独立背景、角色状态和可动道具。
5. 生成中文 TTS、字幕时间戳、音效和背景音乐。
6. Director 只输出受约束的 Scene JSON，不输出或执行任意代码。
7. 用户可以预览、暂停、全屏观看、重做单个镜头，并最终发布为互动网页。
8. 在稳定的播放器之上，再增加 MP4/WebM 等视频导出。

## 产品分层

| 层 | 责任 | 不负责 |
|---|---|---|
| Story Director | 故事改写、分场、镜头与动作规划 | 执行任意 JS |
| Asset Pipeline | 角色、背景、道具、音频的生成与后处理 | 决定播放逻辑 |
| Scene Contract | 描述对象、动作、时间、字幕、声音 | 绑定具体渲染实现 |
| Scene Runtime | 确定性地渲染和播放 Scene JSON | 理解“兔子”“木屋”等故事语义 |
| Player / Editor | 播放控制、全屏、预览、局部重做 | 绕过 Schema 直接改运行时代码 |

## 两分钟意味着什么

技术上，一个 GSAP 时间轴可以直接运行 120 秒，本项目现已用单场景样片验证这一点。但正式作品不应把两分钟硬塞进一个背景：

- 单场景 120 秒：适合验证长时间轴、分段旁白、暂停/恢复、进度与全屏。
- 正式 2 分钟作品：应进入多 Scene 编排，每个场景短而明确，场景切换时加载/释放资产。

所以当前 120 秒样片是能力验证，不代表视觉丰富度已经达到最终成片标准。

## 当前边界

当前版本已经拥有：受约束 Scene JSON、Zod 校验、PixiJS 渲染、GSAP 时间轴、预生成中文录音旁白、字幕、程序雪花、可重复播放和画面全屏。

下一阶段的优先级是：

1. 多 Scene 播放与场景切换。
2. 真正的 TTS 音频文件与时间戳。
3. Director 结构化输出。
4. 角色一致性的素材生成管线。
5. 镜头级重做与可视化编辑。
6. 视频导出。

## 明确不走的方向

- 不让 AI 为每个故事重写一套前端。
- 不把第三方模型返回的代码直接执行。
- 不依赖非公开、随时可能失效的服务接口作为核心生产能力。
- 不在运行时逐帧调用生成模型。
- 不在多场景、时间戳和资产一致性尚未稳定前堆叠复杂 Agent。
