# 故事验收与成本评测 v1.1

更新：2026-09-11。v1.1 用于后续制作；第四篇仍按原 v1 留存首次结果，复审单独记录，不回写首版成绩。

每轮制作前固定规则。程序通过、故事表达合格、孩子愿意玩是三个不同结论。当前样板只是工程与内容设计基线，不能作为教育效果的金标准。

## 必须通过的工程检查

| 检查 | 执行与判断 |
|---|---|
| 合法结构、已知能力与证据引用 | `npm run stories:validate`；字段、ID、节点类型、槽位、目标引用 |
| 可走通且可结束 | 同上；无自动循环、无不可达节点、每节点有结束路径 |
| 作者用例覆盖 | 同上；执行 acceptance，覆盖全部节点与选择，结尾吻合 |
| 回归与可播放 | `npm run quality`；原活动与通用 UI 路径、音频、lint、构建 |
| 不靠改引擎作弊 | 对照开始时的 git 状态，只核对本轮新增变化；新故事不改运行时代码、前三个故事或测试 |
| 视觉与声音 | 与工程验收分开，按下述预览等级记录；没有实际检查的维度保持 pending |

验收用例由作者写，可能与作品共享错误；因此程序通过只是“按写下的规则运行”。必须另看角色动机、画面后果和家长观察，不能把同一个模型的自我评分当成独立证明。

结构反例已经进入自动测试：不存在的资产/依据、不可见点击目标、重复槽位、错误目的地、孤立节点、自动循环、互动死路、给自由选择判错、用例遗漏或不合法。不要删掉这些测试让作品通过。

## 内容人工量表

每项 0/1/2 分：0=不成立，1=需要明显修订，2=具体可见且前后一致。作者可先用量表自查，必须标明身份；成人或其他审阅者的复审单列，日后可请幼教专业人员校准。模型评分只作辅助，不称为人工审核。

| 项目 | 2 分的可观察标准 |
|---|---|
| 角色动机 | 能指出角色想做什么、为什么需要孩子参与 |
| 动作与后果 | 每个必要操作都有与剧情相符的画面变化，consequence 与实际一致 |
| 自主性 | 自由选项各自成立，角色回应不同，没有隐藏的道德标准答案 |
| 语言与反馈 | 简短可听懂，提示具体，鼓励与行为有关，无羞辱/强迫 |
| 教育依据 | 目标具体、出处真实、适龄边界清楚，不声称本作品已验证有效 |
| 素材与演出 | 角色和道具一致，等待有意义，静音/减弱动画时结果仍可理解 |

项目起始门槛：总分至少 10/12、无 0 分项；缺少必要许可、编造研究、危险生活引导或强制羞辱直接不通过。这是项目验收门槛，不是教育领域通用量表。保留修改前后结果。

## 分层验收与低成本预览

| 层级 | 默认做什么 | 能证明什么 / 不能证明什么 |
|---|---|---|
| 数据 | 单篇 validate；审阅命令的前后差异 | 结构和作者路径正确；不证明剧情合理 |
| 内容 | 按规范逐项引用节点、实际台词和状态，列出缺陷 | 可离线查出矛盾；自查不等于独立审稿 |
| 工程 | 台词定稿后 audio:generate + 一次 quality | 共享 UI 测试自动走本篇所有 acceptance；jsdom 模拟配音，无真实布局和听感证明 |
| 预览 | 纯 JSON、已有资产默认 computer use 为 0；视觉与播放待用户抽查 | 不得将“不检查”写成“无问题” |
| 风险预览 | 新资产、布局/播放器变更或具体缺陷时，针对受影响节点与一个窄视口检查；用户要求优先 | 只记实际查看范围，不重复所有旧故事和通用控件流程 |
| 家庭 | 真实手机体验与儿童观察 | 单独记录，不能由模型验收替代 |

低成本模式允许交付“工程通过，内容已审，视觉/实机待验证”，不等于完全验收通过。截图和全量 DOM 输出不作为每篇默认交付物。

内容检查至少包含：天气连续性、双方同意证据、不识字操作提示、实际后果、共同分工、具体反馈。每个发现都写 `node/choice → 证据 → 最小改法`。本次第四篇证明，已有量表的 2 分标准需要证据约束；不要只用总分盖过明显矛盾。角色动机有字面描述也不代表协商已经演出来。

## 家庭试玩

不要求孩子接受测验。一次选择一个故事，观察：会不会看角色反应；是否用动作或语言表示理解了发生的事；在哪句台词等待不耐烦；是否主动选择或重玩；生活里有没有自然提起相关活动。记录成人提示程度，避免提示量不同造成误判。

试玩意愿与理解分开记录。完成快、点击多、重玩多均不能单独证明学习效果。真实手机音频策略、触控与扬声器听感需要实机确认；电脑手机视口不替代这一项。
