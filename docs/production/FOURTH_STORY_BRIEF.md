# 第四个故事独立任务书：雨后的花园小聚会

状态：**已完成两轮内容修订并通过本地工程校验；内容评分、修订版预览、实机与家庭试玩待确认**，见[复审记录](runs/fourth-story-review.md)和[修订记录](runs/fourth-story-revision.md)。以下保留原实验任务要求。本任务书只给目标、情境和限制，不提供节点、台词、选择路径或成品 JSON。前三个样板是参考案例，第四个用于检验模型能否独立组合已有能力。

## 创作输入

- ID：`garden-gathering`。标题可在保持题意的前提下调整。
- 受众：3–4 岁亲子共玩，不要求识字；语言理解需要时由家长支持。
- 情境：雨后的草地上，两位森林朋友想准备一次小聚会。场景中有野餐篮和花，朋友们的准备愿望不完全一样。
- 一个主要目标：在共同准备中，体验说出各自想法并商量一个双方接受的行动安排。感知或顺序任务只能辅助情节，不额外增加教学考核。
- 原创角色与故事；只引用已有教育依据 ID，不借用知名商业动画角色。
- 必须有至少一个改变可见场景的共同操作，以及至少一个双方都能接受的自由选择；至少两个可到达的结束状态，不要求复杂分支树。
- 允许复用现有物体、角色、雨后/草地氛围及有限动效。不要求新美术、物理模拟、拖拽、实时语音识别或视频生成。
- 不能把前三个故事仅换标题、角色、颜色后交付。具体愿望、行动因果和收尾需服务这个聚会情境。

建议先看 `flower/basket` 与现有角色、场景能力，决定哪些内容确实能表现。故事可以简短，不为凑节点或分支加入无关任务。工程限制见生产规范。

## 交付边界

新故事只能通过数据文件进入当前播放器；如果确实无法表现某个必要情节，记录 `capability_gap`，这是有价值的评测结果。不要通过增加按故事 ID 判断的 JSX/CSS 分支完成任务。

验收时用户重点看：是否真正减少了逐故事编程、是否能理解角色动机、自由选择是否成立、是否出现描述与画面不符、人工修稿到底花了多久。模型更便宜是否意味着总成本更低，需要本次真实记录才能判断。
