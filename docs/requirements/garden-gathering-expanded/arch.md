# 花园完整故事版：架构与决策

## 1. 状态、依据与边界

REQ-GARDEN-EXPANDED；架构 v0.1，2026-09-13，待用户确认。引用 [PRD v0.3](prd.md)、[Design v0.2](design.md)、[架构基线 v1.0](../../sdd/arch.md)。代码基线 `9f6cf8b`，本轮开始工作区干净。

用户授权落实 Design review 并进入架构；本轮只修改需求/设计并新增架构、计划文档。新故事、能力扩展、音频及共享规则均未实现，性能与听感没有新测量结果。

维持 React/SVG/CSS、完整场景快照、静态分发、预生成声音。不增加后台、运行时 LLM、条件变量、状态继承、依赖或按故事 ID 的播放器分支。新包自动发现；旧包和历史音频保持原样。

## 2. 核心决策

| 决策 | 推荐方案 | 原因与边界 |
|---|---|---|
| 剧情状态 | 34 个完整节点，四条路径各 18 节点、4 次选择 | 两种布局各自保留；只有同布局内音乐分支汇合 |
| 背景 | 新增通用 `meadow-after-rain` | 放晴、花丛向中间延伸、静态水珠与少量水洼；不新增可点击位，不把花塞进天空槽 |
| 节点上限 | 新 schema 1.1 允许 4～40；旧 1.0 保留 4～24 | 34 加 6 个修订余量；40 是可调整的产品边界，不是性能阈值，不无限放开 |
| 自动开场 | 新 1.1 允许 start 为 interactive 或 beat，禁止 ending；1.0 保留 interactive | 既有“走进故事”提供主动启动，不为契约额外加剧情点击 |
| 声音 | 先做候选试听；不足时优先采用制作时合成的有限短音效 | 优先复用单条本地音频的生命周期，不新增运行时双通道或编排器 |

### 2.1 版本兼容

新故事声明 `schemaVersion: 1.1`、`catalogVersion: 1.1`；现有包继续 1.0/1.0，不批量改写版本。新运行时接受这两组明确配对，拒绝未知版本与不支持的混合组合。

catalog 1.0 只允许原有背景/能力；1.1 增加雨后背景。不能只把全局 `catalogVersion` 改成 1.1，因为当前 `z.literal(catalogVersion)` 会使所有旧包失效。实现时保留按版本的能力清单和验证，源枚举为权威；语音条款以当前 speech schema 为准，不回退历史文字描述。

共享节点形状、图检查与引擎继续复用；用版本化上限、起点与能力检查区分协议。若采用联合 schema，确保 `z.toJSONSchema` 能导出分支限制；不能把 1.1 能力悄悄开放给 1.0。新增声音字段只在最终决定音效方案后列入 1.1。

旧运行时不承诺能读 1.1。源码、故事 JSON、导出目录和静态资源须作为同一构建交付，禁止把新包单独投放给旧运行时。通用基线更新版本说明与兼容决策，原历史验收结论不改写。

### 2.2 背景布局

`StoryBackdrop` 增加新背景分支，复用花形或抽出局部 SVG 绘制片段；不引入图片服务。水珠/水洼静态、不可交互、不遮挡操作区。花丛位置以 Design 为候选，四种布局、320/375/430px 分别验证实际图形邻接和遮挡。

保持已有槽位与 CSS 尺寸，不整体调整旧故事。背景需同时适配舞台及故事卡调用，不把新背景只做在播放器内。右槽篮子不能遮完花，中槽篮子须实际接近花丛，左槽篮子仍处于能看花的同一场景。

## 3. 声音决策：候选试听先于全量实现

目前 `PackPlayer.narrate` 每幕只请求一条旁白音频；`EdgeAudioProvider` 用同一个媒体元素播放，以 generation 忽略过期回调。`useInteractionGuard` 同时等待最短演出与音频结束，并设 20 秒故障释放。经典 `AudioManager` 属于独立时间轴，不能直接引入故事播放器作为第二套音效系统。

| 方案 | 优点 | 代价 / 决策 |
|---|---|---|
| A 纯语音节奏＋现有动作 | 无声音管线扩展 | 体验未知；必须听 x04c/x06c/x04d/x06d，不能默认高潮成立 |
| B 制作时把短音效与对白合成为节点音频 | 保持现有播放、暂停、静音、解锁语义；未来故事可复用有限 cue | 推荐的最小补救方案；需要素材登记、混音缓存及验收 |
| C 运行时独立音效通道 | 可按每次触摸即时触发或独立混音 | 需同步取消、媒体许可、双完成条件；当前固定节点演出不需要，暂不选 |

架构确认后，先制作少量不发布的候选片段，由用户试听决定 A 是否足够。若不足，按用户已确认的架构制作 B 对照片段；确认后才批量生成。不得通过延长台词或多加点击补救。当前尚未选择最终声音，不把此决策未发生写成“配音完成”。

### 3.1 B 的有界契约（条件实施方案）

- 新节点可选 `soundCue`，只接受有限注册 ID，例如 `drum-short`、`drum-clap-short`。它表示制作时合成的一段短声音，不接受 URL、任意文件路径、时间轴或代码。
- 一个节点最多一个 cue，制作成一次短节奏；不循环。预期 cue 长度 0.6～1.5 秒，为拟定制作约束，实际素材时长须测量。组合鼓/拍手先制作成固定片段，不引入运行时 sequencer。
- 音乐节点在入场时先播 cue，再接角色对白；cue 前缀期间现有 play 动作开始。不得同时让角色念相同“咚咚”压住音效；最终台词在试听时调整，字幕只对应实际人声，不把非语言声音写成已朗读台词。
- x04c/x04d 用 drum-short；x06c 用 drum-clap-short；x06d 用 drum-short。邀请节点 x05c/x05d 不播放背景节奏，静待儿童操作。尾声无 cue，保持安静。
- cue 来源为授权可复用素材或项目自行制作，记录来源、许可/作者、哈希、长度与人工试听；不凭文件名推断授权。无合适素材则报告，不下载来源不明的声音。
- 合成缓存键包含原语音 clip 身份、cue 内容哈希、混音参数与混音版本。只更新受影响的新故事最终播放映射；原纯语音文件与历史索引记录保留。
- `audio:pronunciation` 仍覆盖全部实际人声；cue 是非语言音频，不伪造读音审阅。新增验证核对最终映射、合成产物存在、cue 注册有效、时长有界，并保证最终音频没有截断。
- 制作时使用本地混音工具；先确认环境是否具备合适工具，再决定是否需要安装。新工具安装及素材采购不隐含在本架构批准内。生成候选不能覆盖正式映射；正式发布需在内容/声音确认后执行。

### 3.2 生命周期与失败

采用 A/B 均只播放单条最终音频，不新增浏览器媒体元素。暂停、隐藏页面、退出、重玩、重听沿用取消旧音频和 generation 保护；恢复重播当前节点完整音频。静音停止整条声音并保留最终画面；减弱动态不影响台词和状态。

音频结束才释放正常播放；最短 1.8 秒与 20 秒故障上限保持。单段合成音频须明显短于看门狗上限，超过则制作失败，不能以看门狗截断充当正常完成。播放拒绝/文件缺失仍允许有限等待后继续，保留字幕，不宣称自动降级为另一条原始音频。自动节点在真实手机上的媒体许可问题需要实测，不从桌面工具推断正常。

## 5. 测试、规模与回退

必须新增/调整的有意义检查：

1. 旧四包按原版本解析；1.0 的 25 节点被拒绝；1.1 的合法 40 节点图通过、41 节点被拒绝。边界测试必须使用有效且可达可结束的图，避免被其他错误遮蔽。
2. 1.0 beat 起点被拒绝；1.1 beat 起点通过；ending 起点、自动循环、未知版本、版本/背景不匹配仍拒绝。导出结构与源约束一致，语义图检查继续独立运行。
3. 四条路径逐步断言布局：选择后篮子不复位、鼓在中间；拍手 target=fox，反馈狐狸加入；尾声之前不出现结束区。
4. 现有播放器测试使用固定 `settle` 时间和“重玩后等于 pack.start”假设，自动开场后该断言不再适用。改成有限逐节点推进到交互/结尾，另断言重玩瞬间 start 和后续自动开场；不无限推进定时器掩盖循环。保留旧故事行为断言。
5. 有限自动开场、暂停/恢复、快速点击、静音、声音失败、退出和过期回调覆盖。B 如入选，增加制作管线素材与缓存测试，播放器不需复制音效状态机。

规模判断：图校验当前含按节点遍历/可终止性检查，部分工作为二次复杂度；34～40 的有界规模应实测，不承诺无成本。新增包被 eager glob 加入主构建，JSON 与 SVG 会增加包体；MP3 为静态资源，不等于 JS bundle。

实现前后记录相同环境下的单篇/全量校验耗时、原始与 gzip 故事 JSON 字节、构建入口 JS 增量、音频总量；比较 34 与合法 40 节点样本，不以单次毫秒差异作性能结论。单次正常路径为 18 节点；本包图无重试循环，全局仍允许旧故事有界语义下的人工重试，不把最大节点数当最长会话时长。

质量门禁：按计划运行必要测试及一次 quality；若新故障或代码变化再重跑相关部分。视觉/听感/手机与家庭结果独立记录。当前没有本次性能数字。

回退：实现时保留旧四包和所有旧资源；撤销新包及其扩展，或恢复上一完整源码/构建版本。不要单独退 schema 留下 1.1 包，因为 eager 校验会阻断库加载。B 如未被接受，不发布合成映射，继续使用 A 或报告体验未达成，不删除候选作为证据。
