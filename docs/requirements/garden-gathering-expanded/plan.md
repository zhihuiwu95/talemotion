# 实施与验收计划

REQ-GARDEN-EXPANDED；v0.1，2026-09-13；依据 [架构 v0.1](arch.md)、[Design v0.2](design.md)、[PRD v0.3](prd.md)。状态：待架构确认，以下步骤尚未执行。

用户要求每完成一步先确认。本计划将原步骤 4 拆为声音试样与内容实现两个检查点，因为声音决定应在全量实现前解决。每个检查点交付具体结果后等待用户；步骤内常规编辑、检查无需逐条确认。

## 4A. 音乐候选与最小视觉样稿

前提：用户确认架构及本步骤。

- 重新检查 Git，保留期间他人改动。为音乐片段审定少量最终候选人声及读音，使用采样/非发布路径生成 A；不先注册未通过契约的新包，不改正式播放索引。
- 用户试听 A；如不足且架构中 B 获准做试样，检查本地混音工具、登记可用素材、制作 B 对照。提供真实可听的片段与来源，不只描述预期。
- 为 L0/L1/LF/LG 制作可检查的静态 SVG 构图样稿，验证花丛、中槽篮子、右槽篮子的空间关系。这是样稿，不提前实现播放器。沿用现有造型与尺寸，不使用外部图像生成。
- 核对角色、花、道具与水洼不遮挡；实际像素与真实浏览器热区分开记录。需 computer use 时先明确用途并获确认。

交付：候选声音、四布局样稿、选择 A/B 的证据与能力清单。用户确认后开始 4B；不能把用户听过 A 自动当成批准 B。

## 4B. 契约、背景与故事实现

前提：4A 的声音和构图方向已确认。

- 实现 schema/catalog 1.1 的兼容配对、40 节点上限、beat 起点及新背景；旧规则保留。
- 如 B 入选，实现有限 cue 与制作端合成；否则不新增未使用的 cue 字段/模块。
- 创建新故事 34 节点及四条路径，逐幕完整保留布局，所有台词/提示/选择引用与 Design 对齐。必要变动先记录，不悄悄删尾声或增加教学任务。
- 同步受影响生产能力说明、规范与生成导出；保留历史运行记录。为新台词完成发音审阅表及 JSON 标注。
- 完成版本/图/路径/开场与声音相关测试。运行单篇 validate、review、audio:pronunciation；review 内容逐项对应 AC，不能只报 schema 通过。

交付：可检查 JSON、必要共享代码差异、生成分镜、内容与读音审阅结果、目标测试结果。此时音频可能仍为候选，不宣称正式配音或完整 quality 已通过。用户确认后才开始 5。

## 5. 正式声音、本地运行与验收

前提：4B 内容及读音审定，用户确认进入本步。

顺序：

1. 运行 `npm run audio:generate -- --publish`；若采用 B，保证该批准流程发布最终合成产物与映射，原音频保留。
2. 运行 `npm run quality`；汇总目标测试、完整工程门禁、构建体积与校验耗时。补全 `validation.md`，区分 mock 与实际音频。
3. 按需运行 `npm run stories:review` 更新全量生成分镜，检查最终 diff 与生成副作用。
4. 启动 `npm run dev -- --host 0.0.0.0`，使用终端实际端口；检查本地路由 `/?story=garden-gathering-party`。为用户提供实际可用入口，不把 localhost 200 当手机 LAN 证明。
5. 新背景的 320/375/430px 布局、拍手/敲鼓反馈、尾声到结束界面时机与声音做针对性验证；computer use 需另获明确确认，未做写待验证。真实手机媒体许可和听感由实际设备验证，不用桌面结果替代。

交付：用户可查看的本地版本、实际验收报告、仍待验证项。用户确认后才讨论追加修改或其他交付；本计划没有提交、推送或部署授权。

## 证据清单

- 四组合完整路径、每条 18 节点/4 点击；开始前不播，重玩重新演出开场。
- 两种布局的篮子位置持续保留，中间鼓真正参与聚会；花景与雨后视觉可辨认。
- 角色操作与反馈对应；音乐有可听证据，尾声无新任务，主要告别完成后才出现结束区。
- schema 旧/新版本、40/41 上限、自动开场、未知能力、生命周期与旧故事回归。
- 音频来源、读音审阅、候选确认、正式文件与索引一致；失败不永久卡住。
- 构建和文件体积实测；视觉、实机、家庭观察与工程结果分别标明，所有未测项保持待验证。
