# TaleMotion 项目级 SDD 基线

版本：v1.0 · 建立日期：2026-09-12。

这里维护跨需求复用的三个基线。先明确本次要解决的问题，再用适用的约束形成设计和实现方案；文档完成不代表功能或体验已经验收。

| 基线 | 回答的问题 | 使用方式 |
|---|---|---|
| [prd.md](prd.md) | 为谁、解决什么问题、做到什么算完成？ | 复制“需求实例模板”，填写本次需求 |
| [design.md](design.md) | 界面、互动、画面和声音必须遵循什么？ | 按规则 ID 引用，设计实例只写本次变化 |
| [arch.md](arch.md) | 用哪些现有能力实现、哪些技术边界必须保持？ | 按规则 ID 引用，架构实例写模块映射与验证方案 |

## 从哪里开始

| 本次工作 | 最小材料与路径 |
|---|---|
| 新增或修订故事，完全复用现有能力 | 直接进入[故事生产工具包](../production/README.md)。选题卡承担需求实例，互动分镜承担设计实例，运行记录引用现有架构；不重复创建三份文档 |
| 小范围文案、样式或缺陷修复 | 用一段变更说明记录问题、范围、适用基线和验收方式；仅补受影响的设计/架构内容 |
| 新功能、新交互、新资产能力、共享播放器变更 | 先建需求实例，再补设计和架构实例；范围较大时先与用户确认需求再编码 |
| 更换技术栈、引入后台或在线生成、改变数据收集边界 | 写需求与架构决策，明确对基线的调整及旧内容兼容方式；不能作为普通故事制作顺带引入 |

功能需求建议放在 `docs/requirements/<需求标识>/`，下面是命名约定，本次没有创建具体需求：

```text
docs/requirements/<需求标识>/
  prd.md          # 本次需求，引用三个基线版本
  design.md       # 本次页面、状态、素材与交互变化
  arch.md         # 本次模块、契约、测试与交付方案
  plan.md         # 复杂任务按需增加，可运行的实施步骤
  validation.md   # 实际结果、证据、未验证项
```

设计实例可以附图或可点击原型，不强制交付 HTML；简单需求可将设计、架构和验证合并到一份需求文档。故事制作继续使用 `docs/production/runs/` 的既有记录方式。

## 三层如何衔接

```text
通用层：prd 模板 + design 约束 + arch 约束
                         ↓ 引用版本和规则
需求层：本次 prd → 本次 design → 本次 arch
                         ↓ 映射验收项
执行层：实施步骤 → 代码/故事/资源 → 验证记录
```

需求实例使用 `REQ-…`、`US-…`、`AC-…`、`P-…` 标识需求、用户故事、验收项和页面/状态。设计沿用页面与验收 ID，架构把它们映射到模块和验证方法。故事内部的 node/choice ID 继续由故事包维护，不额外改名。

每个实例记录：基线版本、本次代码 commit 或工作区状态、适用规则、偏离项、未解决问题。规则满足情况使用“满足 / 待实现 / 待验证 / 不适用（原因）”，不要把引用规则写成验收通过。

## 权威来源与变更

- **本目录**定义通用要求；需求实例描述本次差异，不能无说明地覆盖基线。
- **故事生产细则**以 [STORY_STANDARD](../production/STORY_STANDARD.md)、[CAPABILITIES](../production/CAPABILITIES.md)、[EVALUATION](../production/EVALUATION.md) 为专门来源，本目录引用它们，不复制整套制作合同。
- **可执行契约**以 `src/stories/schema.ts`、`src/stories/catalog.ts` 及验证代码为准；导出的 JSON Schema 和能力目录不能代替语义校验。代码说明当前能做什么，基线说明变更应满足什么；不一致时记录差距，不把代码现状自动当成目标。
- **历史规划和运行记录**保留原日期与结论。早期产品愿景中的动态生产平台是规划，不是当前已实现范围。
- 新增要求只约束新工作及被本次修改影响的部分。本次建立基线不隐含全仓重构、旧故事重制或重新验收。
- 改基线时说明原因、影响、迁移/回退办法并更新版本；小澄清升补丁版本，新增兼容要求升次版本，破坏性变化升主版本。实例固定引用版本，后续变更时再评估是否跟进。
- 沿用用户已有授权；文档状态不额外制造多角色签字或重复确认流程。提交、推送、部署、线上验证仍分别记录授权与结果。
