# TaleMotion 设计约束

版本：v1.0 · 建立日期：2026-09-12 · 类型：通用设计基线。

## 1. 适用范围与原则

本文件管用户看见、听见和操作时发生什么；代码组织与实现方式见 [arch](arch.md)。适用于故事小屋、共享故事播放器、家长陪玩及观察界面；经典动画保留其已有演示形态，改动时按相关规则检查。

规则中的“必须/不得”约束本次新增或修改的部分，“建议”允许按场景说明取舍。文中的当前值来自 2026-09-12 仓库静态核对；新设的尺寸检查目标不是全站实测结果。

- **DES-01 亲子共玩**：儿童操作围绕角色和物体，成人承担解释、设置和观察。不要让儿童先读说明、填表或完成评价才能继续故事。
- **DES-02 故事优先**：画面、台词、操作与后果服务于同一情节；不能用与情节无关的题卡或连续“下一句”按钮代替互动。
- **DES-03 自主与具体反馈**：自由选项都成立；重试描述差异与线索，不扣分、不羞辱、不贴能力标签。不引入倒计时、排行榜、连续奖励或自动播放下一篇。
- **DES-04 可停止**：核心流程提供暂停、声音开关、重听、退出和主动重玩；成人说明不压住儿童操作区域。退出后不留下背景声音。

故事动机、协商、自然事实和生活延伸的内容要求沿用 [STORY_STANDARD](../production/STORY_STANDARD.md)，不在设计基线另设一套评分。

## 2. 信息与页面结构

**DES-05**：沿用“故事小屋 → 选一篇 → 开始 → 演出/选择/反馈 → 结尾 → 主动重玩或返回”的核心路径。新需求只画受影响的页面与状态，沿用 PRD 页面 ID。

| 区域 | 主要信息 | 约束 |
|---|---|---|
| 故事小屋 | 故事题名、画面、适用范围、陪玩提示 | 不把工程状态、模型名称或验收分数放进儿童选故事流程 |
| 故事舞台 | 角色、道具、可操作对象和实际后果 | 画面主体清楚，提示、控件与字幕不遮住目标 |
| 台词与提示 | 谁在说、说什么、下一步能做什么 | 台词与舞台分区；不能只靠文字解释必要动作 |
| 家长控制 | 返回、暂停、静音、陪玩说明 | 视觉上次于故事主体，但可发现、可操作 |
| 结尾 | 角色回应、生活延伸、主动重玩/退出 | 不设置完成成绩或强迫继续 |
| 观察记录 | 自愿保存、查看、导出、清除 | 不挡住儿童结束；明确仅本浏览器保存，清除有确认 |

## 3. 交互状态与声音

**DES-06**：设计实例必须交代本次涉及的以下状态；按钮五态可按实际需要裁剪，触屏不能依赖 hover 才能发现功能。

| 状态 | 用户应得到的反馈 | 允许的动作 |
|---|---|---|
| 未开始 | 可理解的开场和开始入口 | 主动开始、返回、成人查看说明 |
| 演出/台词进行中 | 看得见发生了什么，不误以为点击失效 | 家长可暂停或静音；故事选择受保护 |
| 等待选择 | 可操作物体明确，必要动作已有口头提示或已建立的视觉线索 | 选择、重听、暂停、返回 |
| 重试反馈 | 指出具体差异，不跳过角色回应 | 反馈结束后重新选择 |
| 暂停/陪玩说明 | 舞台停止推进，声音停止 | 继续或返回；继续时重播当前台词 |
| 声音不可用/静音 | 文字和最终画面保留，流程可以继续 | 重听或声音控制、继续操作、退出 |
| 结尾 | 具体感谢或结果，不自动开始下一集 | 主动重玩、返回、成人自愿记录 |

- **DES-07 防误触**：一次手势只触发一次有效选择；上一个状态开始的触摸不能穿透到下一幕。反馈结束前不接受下一次故事选择，且不能用无限等待代替保护。
- **DES-08 配音可用性**：必要操作由实际可播放台词说明；故事包中只有 `line.text` 生成旁白，`cue/label` 不自动朗读。`speaker` 是字幕署名，不代表不同角色声线。
- **DES-09 真实后果**：每个关键选择要能指出前后台词、对象、位置或状态差异；作者写在 `consequence` 中的描述不会自动变成画面。自由选项可以汇合，但先给各自成立的回应。
- **DES-10 故障文案**：用简短可行动的提示，例如声音不可用时请成人读台词；不向儿童展示异常栈、服务错误码或制作术语。错误提示不得承诺实现中不存在的自动恢复能力。

> 2026-09-12 后续需求说明：v1.0 中 text-only / speaker 仅署名的现状描述已由 [Speaker-aware TTS 实例](../requirements/speaker-aware-tts/arch.md) 替代。当前制作支持角色声线身份；正式录音仍明确保留旧版，候选待试听。

## 4. 视觉语言与样式复用

**DES-11**：沿用温暖、清楚的森林绘本风格。使用原创动物、可辨认的物体轮廓、柔和场景色和有留白的纸面；不默认引入外部 IP、广告化奖励视觉或与故事无关的装饰。

现有共享样式值来自 [play.css](../../src/play/play.css)，不是新建的完整 Token 系统：

| 已有变量 | 当前值 | 设计用途 |
|---|---|---|
| `--deep` | `#285e60` | 深青主色 |
| `--green` | `#47745f` | 辅助绿 |
| `--yellow` | `#f3cc75` | 温暖强调 |
| `--paper` | `#fffdf5` | 纸面 |
| `--body` | PingFang SC / Microsoft YaHei / sans-serif | 中文正文 |
| `--title` | Yuanti SC / STYuanti / YouYuan / PingFang SC / sans-serif | 圆体标题与系统回退 |

故事场景另有固定调色：雪蓝 `#dceef5`、雨灰绿 `#d9e7e3`、草绿 `#e4efd7`、日光黄 `#fff2bd`、珊瑚 `#dc8f79`、墨青 `#294e57`。语义和资产以 [CAPABILITIES](../production/CAPABILITIES.md) 为准。`--deep` 与故事墨青用途不同，不强行合成一个值。

**DES-12**：新界面优先复用已有字体、颜色和组件。反复出现的新语义值，在相关样式范围内命名复用；设计实例列出新增值和用途。现有代码仍有直接色值、字号和间距，本次不要求全量 Token 化，也不声称已有完整设计系统。故事资产固有配色不必强行改成界面 Token。

字号、圆角和间距先沿用所修改组件；新布局应在设计实例中明确值与窄屏变化，不只写“参考原风格”。正文须保持可读，标题不能挤掉操作区。圆体不可用时使用系统回退，不依赖远程字体才能正常阅读。

## 5. 触控、适配与可访问性

**DES-13**：以下是本基线为新增/修改界面设定的项目验收目标，不是法律或行业认证，也不是既有界面的全量测量结论。

| 项目 | 本项目检查目标 | 验证方式 |
|---|---|---|
| 儿童主要点击目标 | 热区至少 60 × 60 CSS px；不能相互重叠 | 在最窄目标视口测量实际可点击边界 |
| 家长控制 | 热区至少 44 × 44 CSS px | 检查按钮实际区域，不能只看图标 |
| 相邻独立目标 | 建议至少 8 CSS px 可辨间隔，复杂舞台优先调整位置 | 测量并尝试相邻点击，不能扩大到覆盖别的目标 |
| 窄屏 | 风险预览默认选 320 CSS px 窄视口；375/430 及桌面按布局影响追加 | 无横向溢出；必要目标、字幕、退出入口不被裁切 |
| 矮屏/方向变化 | 核心内容可访问，允许合理滚动 | 检查浏览器工具栏和方向变化，不锁死为单一高度 |
| 键盘与读屏名称 | 可操作元素有名称与可见焦点；弹窗关闭后焦点可合理返回 | 键盘操作与语义检查，视觉检查不能代替读屏验证 |

若需求使用不同设备范围，在 PRD 和设计实例中明确。原样式的 `min-width: 280px` 不是 280px 已完成体验验收的证明。

- **DES-14**：不能只用颜色、声音或运动传达关键含义；物体轮廓、位置、台词和最终画面应互相支持。静音时允许成人读字幕，不承诺不识字儿童可独立理解。
- **DES-15**：支持系统减弱动态效果；关闭动画后仍呈现有意义的最终状态。操作区避免长按选字和拖图干扰，成人输入框须保留正常编辑与选字。
- **DES-16**：故事包目标限于能力目录中允许点击的槽位，远处天空小物不能承担必要触控；不能将未绘制的“空地”当作已经存在的按钮。

## 6. 素材、动效与节奏

**DES-17**：普通故事复用能力目录的 asset、backdrop、slot、mood、motion。新演出先写清“要表达的动作 → 现有能力的差距 → 受影响节点 → 替代或扩展方案”，不能凭文字承诺未实现的碰撞、搬运、骨骼或音效。

当前动作语义、触发条件和时长详见 [CAPABILITIES](../production/CAPABILITIES.md)。`rain` 是持续下雨；`deliver` 是向当前位置移入；`play` 是节奏缩放摆动，不包含独立鼓声。

**DES-18**：动效必须服务于进入、选择反馈或结果表达。新动效写明触发、结束、取消、暂停恢复和减弱动态效果下的表现，不使用持续闪烁或反复强刺激吸引点击。

当前共享播放器最短演出为 1.8 秒，同时等待配音完成；20 秒看门狗是故障恢复上限，不是正常节奏设计。普通作者不修改解锁时长。需要改变节奏时，在设计实例写用户收益，再由架构实例说明生命周期和回归影响。

## 7. 设计实例最小交付与验收

功能需求的 `design.md` 可以按下表填写；纯故事直接使用互动分镜和生产审阅记录。

| 内容 | 必须说清楚的事项 |
|---|---|
| 元信息 | 需求 ID、PRD 版本、本基线版本、适用规则和偏离项 |
| 页面与状态 | 页面 ID、入口、主要信息、操作、结果、退出、关联 AC |
| 布局 | 复用组件/画面，必要尺寸及窄屏变化；需要时附草图或原型 |
| 状态矩阵 | 默认、按下、焦点、禁用、等待、错误等实际涉及状态 |
| 素材与声音 | 复用 ID 或新增清单、来源、实际口头提示、动作前后差异 |
| 动效 | 触发/结束/取消/暂停/减弱动态效果，各自的表现 |
| 验证 | 检查的视口、节点、声音、输入方式，证据与未验证项 |

验收至少检查：主要操作能被发现；每次动作有真实反馈；状态与退出完整；文字不遮主体；静音与减弱动态效果可用；受影响触控目标符合尺寸；许可与内容来源有记录。

纯 JSON 复用默认不使用 computer use，按 [EVALUATION](../production/EVALUATION.md) 标记视觉/实机待验证。新布局、资产、播放器变更或具体播放风险才做针对性浏览器检查；模拟手机视口不替代真实手机音频、扬声器和亲子体验。
