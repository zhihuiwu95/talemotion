# TaleMotion PRD 模板

版本：v1.0 · 建立日期：2026-09-12 · 类型：通用需求母版。

## 使用约定

本文件规定需求怎么写。需求说明用户问题、产品行为和验收结果；视觉参数属于 [design](design.md)，模块、接口、文件及存储实现属于 [arch](arch.md)。需求元信息可以链接技术方案，但不在业务规则里规定组件名称。

当前产品是面向低龄儿童、家长陪玩的互动故事 H5。原活动面向约 2.5–4 岁，现有故事包主要按 3–4 岁设计；具体需求必须填写年龄和成人支持方式，不从 schema 可填年龄范围推断全部年龄已经适用。

项目默认边界：一次选一个故事、自由退出、描述性反馈；无计时排名、积分奖惩、广告、账户或儿童录音采集。在线生成、内容后台、跨设备同步属于独立需求。制作效率、故事表达质量、使用意愿和学习效果分别判断。

### 模板填写规则

- **PRD-01**：每个需求先写问题、目标、包含与不包含范围；假设标明待验证，缺失数字写“未知”。
- **PRD-02**：每条核心用户故事至少关联一个可验证的 AC；整体覆盖正常、异常和边界场景。不适用项写原因。
- **PRD-03**：验收用 Given / When / Then 描述可观察行为，避免“流畅”“有趣”“适龄”单独作为标准。
- **PRD-04**：分清儿童、陪玩成人和内容制作者的需求，只填写本次涉及的角色。
- **PRD-05**：记录指标的观察方法、条件和判断标准；点击、完成或重玩次数不能单独证明学习效果。无线上埋点时可使用自愿家庭观察，不为填表增加采集。
- **PRD-06**：复杂需求先明确待定问题和用户已确认的决定；不编造访谈、许可、成本、签字或测试结论。

纯故事制作使用[生产入口](../production/README.md)的任务书和记录，按上述原则核对即可。功能需求从下面的模板复制；所有章节均需作出判断，小需求可简写，无关项注明“不适用 + 原因”。方括号内容须在进入实施前替换或列为明确的待定项。
